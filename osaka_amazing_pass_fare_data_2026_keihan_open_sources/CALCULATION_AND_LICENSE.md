# 2. 전체 운임 계산 구조

전체적인 생성 방식은 다음과 같다.

```text
주유패스 이용 가능 구간 확정
        ↓
사업자별 역 / 인접구간 데이터 정규화
        ↓
운임 계산용 그래프 구축
        ↓
출발역 → 도착역 최단 운임계산거리 산출
        ↓
사업자별 거리/구수 운임 규칙 적용
        ↓
가산운임·특정운임·계산특례 적용
        ↓
최종 성인 일반 편도운임
        ↓
역쌍별 CSV 사전 생성
```

앱에서는 이 복잡한 계산을 매번 할 필요 없이 생성된 `fares_*.csv` 또는 SQLite 변환본을 로컬 조회하면 된다.

# 3. Osaka Metro 운임 계산 방식

## 3.1 이전 방식에서 변경한 이유

초기 버전은 Osaka Metro가 공개한 **역쌍별 공식 운임구수표 전체**를 파싱하여 5,882개의 역쌍을 구성했다.

정확성은 높지만, 공식 사이트의 대규모 표 배열을 그대로 변환·재배포하는 것으로 해석될 여지를 줄이기 위해 현재 버전에서는 이 방식을 사용하지 않는다.

현재 최종 데이터는:

> **인접역 영업거리라는 사실 데이터 + 공개된 운임 계산 규칙 → 독립 계산**

방식으로 생성한다.

공식 역쌍 구수표는 **결과 검증용 oracle**로만 사용하고 패키지에 복제하지 않는다.

---

## 3.2 계산에 사용하는 데이터

현재 Metro 계산 데이터는 다음으로 축소되어 있다.

- 물리적 역: **109개**
- 인접역 영업거리: **125개**
- 계산 결과: **5,882개 역쌍**

`metro_edges_2026.csv`의 구조 예시:

```csv
operator,line,station_a,station_b,business_km
Osaka Metro,御堂筋線,江坂,東三国,2.0
...
```

즉 공식 전체 역쌍표가 아니라 철도 그래프를 구성하는 **인접구간 사실값**만 저장한다.

---

## 3.3 Step 1 — 운임 계산 그래프 구축

각 역을 node, 인접역 영업거리를 edge weight로 사용한다.

```text
station A
   │ 1.2km
station B
   │ 0.8km
station C
```

출발역과 도착역 사이의 운임 계산에는 **최단 영업거리 경로**를 사용한다.

현재 구현은 Dijkstra 방식으로 최단 영업거리를 계산한다.

Osaka Metro 여객영업규칙 제47조의 최단 영업킬로 계산 원칙을 반영한다.

공식 규칙:
- https://subway.osakametro.co.jp/guide/fare/conditions_carriage/unsoyakan.php

---

## 3.4 Step 2 — 동일역 취급 연결

운임 계산에서 다음 역들은 별도 물리역이지만 동일역으로 취급되는 연결을 추가한다.

- 梅田 ↔ 東梅田
- 梅田 ↔ 西梅田
- 東梅田 ↔ 西梅田
- 心斎橋 ↔ 四ツ橋

그래프에서는 운임 계산용 **0km 연결**로 처리한다.

이는 `fare_exceptions_2026.csv`에 명시적으로 기록한다.

---

## 3.5 Step 3 — 최단 영업거리 → 운임 구수

최단 영업거리를 계산한 뒤 다음 구간으로 변환한다.

| 구수 | 영업거리 | 성인 보통운임 |
|---:|---:|---:|
| 1구 | 3km 이하 | ¥190 |
| 2구 | 3km 초과 ~ 7km 이하 | ¥240 |
| 3구 | 7km 초과 ~ 13km 이하 | ¥290 |
| 4구 | 13km 초과 ~ 19km 이하 | ¥340 |
| 5구 | 19km 초과 | ¥390 |

운임 공식 페이지:
- https://subway.osakametro.co.jp/guide/fare/fare/price.php

---

## 3.6 Step 4 — 특정 운임구수 9개 구간

단순 최단거리 구수보다 우선하는 특정구간을 별도 override한다.

현재 DB에 반영한 9개는 다음과 같다.

| 출발/도착 | 적용 구수 |
|---|---:|
| 中津 ↔ 弁天町 | 2구 |
| 中津 ↔ 緑橋 | 2구 |
| 天王寺 ↔ 鶴橋 | 2구 |
| 新大阪 ↔ 谷町四丁目 | 2구 |
| 新深江 ↔ 昭和町 | 3구 |
| 昭和町 ↔ 森ノ宮 | 3구 |
| 西中島南方 ↔ 西長堀 | 2구 |
| 西田辺 ↔ 谷町四丁目 | 3구 |
| 谷町六丁目 ↔ 長居 | 3구 |

이 규칙 역시 `fare_exceptions_2026.csv`에 저장한다.

---

## 3.7 Step 5 — 夢洲 가산운임

夢洲가 발착역인 경우:

```text
계산된 일반 운임 + ¥90
```

을 적용한다.

공식 가산운임 안내:
- https://subway.osakametro.co.jp/guide/fare/various_fares/kasan/kasan_unchin.php

---

## 3.8 Step 6 — 공식표와 검증

최종 데이터 생성 후에만 Osaka Metro 공식 2026 구수표와 비교했다.

검증 결과:

| 검증 항목 | 결과 |
|---|---:|
| 물리적 역 | 109 |
| 인접 edge | 125 |
| 자체 계산 역쌍 | 5,882 |
| 공식표와 비교한 역쌍 | 5,882 |
| 구수 불일치 | **0** |
| 최종 운임 불일치 | **0** |

즉:

> **5,882 / 5,882 일치**

했다.

공식 구수표는 이 검증 단계에서만 참조했으며, 공식표의 전체 row/cell 배열을 최종 패키지에 저장하지 않는다.

# 4. 다른 사업자 운임 계산 방식

## 4.1 공통 구조

한큐·한신·게이한·긴테쓰·난카이는 기본적으로 다음 구조를 사용한다.

```text
주유패스 대상 인접역
        ↓
인접역 영업거리/계산거리
        ↓
사업자별 그래프
        ↓
최단 운임계산거리
        ↓
거리별 기본 운임
        ↓
가산운임 / 특정운임 override
        ↓
최종 운임
```

거리 구간 판정 시 사업자 규칙에 따라 필요한 경우 소수 영업거리를 다음 운임계산 km로 올림 처리한다.

---

## 4.2 한큐전철

계산 구조:

```text
주유패스 대상 한큐 구간
→ 최단 영업거리
→ 한큐 거리별 성인 보통운임표
→ 최종 운임
```

현재 계산된 역쌍: **78쌍**

주의:
- 일부 짧은 인접거리 값은 하나의 완전한 공식 인접거리 매트릭스에서 일괄 추출한 것이 아니라 현행 경로/거리 정보와 교차검증하였다.
- 해당 row는 `source_quality=cross_checked`로 표시한다.

사이트 이용조건:
- https://www.hankyu.co.jp/sitepolicy/index.html

## 4.4 게이한전철

현재 계산된 역쌍: **66쌍**

게이한은 **공식 게이한 사이트를 생산 데이터 출처에서 제거**했다.

현재 생성 구조:

```text
Japanese Wikipedia
→ 京阪本線 / 中之島線 인접 영업거리

국토교통성
→ 2025-10-01 이후 거리별 성인 보통운임
→ 中之島線 +60엔 가산운임

Japanese Wikipedia
→ 大江橋 = 淀屋橋
→ なにわ橋 = 北浜
  (天満橋以東 운임동등 규칙)

우리 계산 코드
→ 최단거리 + 운임규칙 + 가산/동등 규칙
→ 최종 운임
```

거리별 운임:
- https://www.mlit.go.jp/common/001879895.pdf

中之島線 운임동등/영업거리:
- https://ja.wikipedia.org/wiki/%E4%BA%AC%E9%98%AA%E4%B8%AD%E4%B9%8B%E5%B3%B6%E7%B7%9A

京阪本線 영업거리:
- https://ja.wikipedia.org/wiki/%E4%BA%AC%E9%98%AA%E6%9C%AC%E7%B7%9A

가산운임:
- https://www.mlit.go.jp/common/001287195.pdf

이전 버전의 `大江橋↔京橋=180`, `大江橋↔千林=240` 하드코딩도 제거했다.
현재는 `大江橋`을 `淀屋橋` 기준으로 재계산하는 일반 규칙으로 같은 결과를 산출한다.

# 6. 라이선스 / 저작권 판단의 기본 원칙

## 6.1 사실 데이터와 저작물을 구분해야 한다

일본 문화청은 저작물 판단과 관련하여 **단순한 사실이나 데이터는 저작물에 해당하지 않는 경우**를 설명하고 있다.

예:

- 역 이름
- 영업거리 2.0km
- 운임 ¥240
- 1구/2구 같은 운임 구분
- 특정 역 사이에 특정운임이 적용된다는 사실

같은 개별 사실값은 일반적으로 문장·그림 같은 창작적 표현과 성격이 다르다.

문화청:
- https://www.bunka.go.jp/seisaku/chosakuken/kaizoku/faq.html
- https://www.bunka.go.jp/seisaku/chosakuken/seidokaisetsu/chosakukensha_fumei/

그러나 문화청은 동시에 **소재의 선택 또는 배열에 창작성이 있는 편집물이나 데이터베이스**는 별도로 보호될 수 있다고 설명한다.

따라서 다음 두 가지는 동일하지 않다.

### 상대적으로 위험이 낮은 방식

```text
A역–B역 = 2.0km
1~3km = ¥180
```

이라는 사실값을 바탕으로 우리 프로그램이 독립적으로:

```csv
origin,destination,distance,fare
A,B,2.0,180
```

을 생성하는 것.

### 주의가 필요한 방식

공식 사업자가 만든:

- 전체 운임표
- PDF
- 역쌍 매트릭스
- 노선도
- 표 배열
- 설명문
- 화면 디자인

등을 그대로 복제하여 앱이나 GitHub에 배포하는 것.

# 7. 현재 패키지에서 라이선스 리스크를 줄인 방법

현재 데이터 패키지는 다음 원칙을 적용한다.

1. **공식 PDF 자체를 포함하지 않는다.**
2. **공식 노선도·지도 이미지를 포함하지 않는다.**
3. **회사 로고를 포함하지 않는다.**
4. **공식 사이트의 설명문을 그대로 복제하지 않는다.**
5. 운임·거리·역명 등 필요한 **사실값만 정규화**한다.
6. 역쌍 운임은 가능한 한 **우리 그래프와 계산 알고리즘으로 파생 생성**한다.
7. Osaka Metro의 공식 5,882칸 역쌍 운임표는 **검증용으로만 이용**하고 재배포하지 않는다.
8. 각 row 또는 규칙에 `source_url`, `source_quality`를 유지한다.
9. 계산 결과와 원본 표현물의 권리를 구분한다.

이 구조는 공식 표를 그대로 복제하는 것보다 저작권 리스크를 상당히 줄이는 방향이다.

## 게이한 — 공식 사이트 데이터 의존 문제 해결

이전 버전에서는 게이한 공식 사이트의 영업거리·운임표·특정운임 페이지를 생산 데이터 출처로 사용했기 때문에 사이트 이용약관 리스크가 상대적으로 높았다.

현재 버전에서는 이를 다음과 같이 교체했다.

- 역/노선 마스터 후보: 駅データ.jp
- 京阪本線·中之島線 영업거리: Japanese Wikipedia
- 거리별 보통운임: 국토교통성 공개자료
- 中之島線 +60엔: 국토교통성 공개자료
- 특정운임 하드코딩: 제거
- `大江橋=淀屋橋`, `なにわ橋=北浜` 규칙으로 자체 계산

따라서 **`keihan.co.jp`의 콘텐츠를 생산 DB의 원천으로 재배포하는 구조는 제거되었다.**

Wikipedia는 Wikimedia 이용조건상 CC BY-SA 4.0으로 상업적 재이용이 가능하되, 저작권이 있는 표현물을 재이용하는 경우 귀속 및 ShareAlike 조건을 지켜야 한다.
현재 패키지는 보수적으로 출처와 라이선스 메타데이터를 유지한다.

- Wikipedia Terms: https://foundation.wikimedia.org/wiki/ToU
- 駅データ.jp 이용규약: https://ekidata.jp/agreement.php

실제 패키지의 상세 provenance는 `keihan_source_provenance_2026.csv` 및 `KEIHAN_DATA_NOTICE.md`를 참조한다.

# 9. “라이선스 문제는 없는가?”에 대한 결론

## 저작권만 놓고 보면

현재 방식은 비교적 안전한 방향이다.

특히 Osaka Metro를:

```text
공식 전체 역쌍표 복제
```

에서:

```text
인접거리 사실 데이터
+
공개 운임 규칙
+
우리 자체 경로계산
=
독립 생성 운임 DB
```

로 변경한 것은 중요한 개선이다.

또한 공식:

- PDF
- 지도
- 이미지
- 로고
- 설명문
- UI 디자인

을 배포하지 않기 때문에 원본 저작물의 직접 복제 위험도 줄였다.

## 하지만 “문제 없음”을 보장할 수는 없다

이유는 **저작권과 웹사이트 이용약관은 별개의 문제**이기 때문이다.

개별 운임·거리 같은 사실값이 저작권상 보호 대상이 아니더라도, 특정 사이트를 이용하여 데이터를 취득할 때 그 사이트의 이용조건이 별도로 적용될 수 있다.

특히:

- 게이한: **주의도 높음**
- 긴테쓰 / 난카이 / 한큐 / 한신 / Osaka Metro: **공식 콘텐츠 재배포 금지 조건 주의**
- 주유패스 공식 사이트: **로고·이미지·문장 복제 금지 주의**

라고 보는 것이 안전하다.

공식 PDF나 전체 표는 넣지 않는다.

# 12. 코드와 데이터 라이선스도 분리 권장

GitHub 공개 시 전체 프로젝트를 무조건 하나의 MIT License로 묶기보다 다음처럼 분리하는 것을 권장한다.

```text
/code
  MIT License

/data
  DATA_NOTICE.md
```

`DATA_NOTICE.md`에는 다음 취지를 명시할 수 있다.

```text
Fare results in this project are independently calculated from
factual station, distance and publicly available fare-rule information.

Original operator PDFs, maps, logos, images, website layouts and
proprietary full fare tables are not redistributed.

All rights in original source materials remain with their respective
rights holders.

Source URLs are provided for provenance and verification.
```

이는 “제3자 원본 자료까지 MIT로 재라이선스한다”는 오해를 피하기 위한 것이다.

공식 사업자 로고를 사용하지 않는다면 텍스트 사업자명만 표시하는 방식이 가장 단순하다.

# 14. 유지보수 시 규칙

운임 개정 시에는 기존 CSV를 직접 수정하기보다:

```text
원천 운임 규칙 업데이트
        ↓
인접거리/특례 검증
        ↓
전체 역쌍 재계산
        ↓
공식 검색/공식 표로 검증
        ↓
새 버전 CSV 생성
```

방식으로 관리한다.

데이터에는 최소한 다음 메타정보를 유지하는 것을 권장한다.

- `effective_date`
- `generated_at`
- `source_url`
- `source_quality`
- `calculation_method`
- `rule_version`

# 15. 최종 판단

현재 패키지는 **공식 운임표를 그대로 복제해 배포하는 DB가 아니라, 사실 데이터와 공개 운임 규칙을 이용해 독립적으로 계산한 파생 운임 DB**를 목표로 한다.

특히 Osaka Metro는 공식 5,882개 역쌍표를 최종 데이터 생성원으로 사용하지 않고:

- 109개 역
- 125개 인접 영업거리
- 최단거리 규칙
- 동일역 취급
- 9개 특정구간
- 夢洲 가산운임
- 1~5구 운임

으로 전부 다시 계산하며, 공식 구수표는 결과 검증에만 사용한다.

이 방식은 라이선스·저작권 리스크를 줄이는 데 적절한 구조다.

다만 **각 사업자의 사이트 이용약관까지 포함해 상업적 이용이 완전히 자유롭다고 보장할 수는 없으며**, 게이한은 현재 대체 출처와 자체 계산 구조로 전환했으며, Wikipedia 귀속/라이선스 및 국토교통성 출처 고지를 유지한다.
