## 1. 첫 스캔 안내 및 실패 상황별 설명

### 검토 목적

처음 설치한 사용자가 지원 대상과 스캔 방법을 이해하고, 스캔에 실패했을 때 다음 행동을 알 수 있게 한다.

### 검토할 내용

- 실물 교통카드를 휴대폰 뒷면의 NFC 위치에 대는 방법을 짧게 안내한다.
- 지원 카드와 Android 기기의 NFC-F 읽기 지원 필요 조건을 이해하기 쉽게 설명한다.
- NFC 꺼짐, NFC 또는 읽기 기능 미지원, 카드 읽기 실패 등을 실제로 판별 가능한 범위에서 구분한다.
- 실패 유형에 맞춰 NFC 켜기, 카드 위치 조정, 카드를 잠시 고정한 뒤 재시도 등 다음 행동을 안내한다.
- 기존 안내와 오류 처리를 먼저 확인하고, 이미 충분한 내용은 중복 추가하지 않는다.

### 확정된 구현 방향 (2026-10-19)

- 최초 실행 강제 안내 없이 홈의 `카드를 어디에 대야 하나요?`에서 스크롤 가능한 하단 도움말을 연다. 새 영구 저장이나 최초 실행 플래그는 추가하지 않는다.
- 홈 NFC 문구는 실제 어댑터 상태(켜짐·꺼짐·미지원·확인 불가)로 표시하고 설정 복귀 시 갱신한다. 켜짐만으로 NFC-F 지원을 확정하지 않는다.
- 오류 종류별 설명과 설정 이동·재스캔·도움말을 제공한다. 시간 초과를 미지원 카드로 단정하지 않고, 이용내역 없음과 취소를 일반 오류처럼 표시하지 않는다.
- 스캔 화면의 기술 용어를 줄이고 막대를 실제 읽기 진행률이 아닌 제한 시간 경과로 설명한다. 실패 시 기존 성공 결과를 보존한다.
- 기존 하늘색 테마와 라이트·다크 모드, 카드 해석·현재 세션 한정 데이터 처리 정책을 유지한다.

## 2. 현재 읽은 기록의 지출 합계

### 검토 목적

현재 스캔한 이용내역에서 사용자가 필요한 지출만 골라 확인할 수 있게 한다.

### 검토할 내용

- 현재 선택한 필터에 해당하는 이용내역의 이용 금액 합계(개별 기록 선택 모드는 제공하지 않음).
- 교통·물품 구매·충전 등 거래 유형별 구분 및 집계.
- 충전은 지출과 분리하고, 금액이나 유형이 미확인인 기록은 임의로 계산하지 않는다.
- 카드에서 읽은 최근 기록에 한정된 합계임을 명확하게 표시한다.
- 현재 세션 안에서만 계산하여 이용내역 영구 저장 없이 제공할 수 있는지 검토한다.

### 확정된 구현 방향 (2026-10-21)

- 개별 기록 선택 모드나 체크박스를 추가하지 않고 기존 전체·교통·결제·충전·미확인 필터 아래에 요약을 표시한다.
- 전체는 확인된 철도·버스·물품 구매 지출, 교통은 철도·버스, 결제는 물품 구매를 합산한다. 충전은 확인된 잔액 증가액만 별도 집계한다.
- 미확인은 금액 대신 기록 건수만 표시한다. 미계산·확인 필요·특수 거래는 임의 합산하지 않고 합계 제외 건수를 표시한다.
- 이미 전체 스캔에서 계산한 개별 금액만 더한다. 필터에 남은 기록끼리 잔액 차이를 다시 계산하지 않는다.
- 현재 스캔한 최근 기록 범위임을 알리며 영구 저장·새 전송은 추가하지 않는다. 재스캔·초기화 시 입력 기록에 따라 요약도 갱신한다.
- 기존 하늘색·공통 카드·타이포그래피를 재사용하며 내역 카드의 우측 하단 잔액 정렬은 유지한다.
- 후속 확정: 전체·교통·결제의 제목은 간단히 `지출 합계`로 통일한다. 합산/제외 건수와 계산 기준은 기본 숨김으로 두고 카드 탭으로 아래에 펼친다. 다시 탭하거나 필터를 바꾸면 접힌다. 충전·미확인 제목은 기존 구분을 유지한다.
- 최종 UI는 제목·금액의 가로 배치이며 금액은 오른쪽 정렬, 화살표는 카드 내부 오른쪽 16dp, 금액과 화살표 사이는 8dp로 유지한다. 현재 구현·전체 자동검증 238개와 대상 분석이 완료됐으며 실기기 대조는 별도다.

### 유의 사항

- 카드에 남아 있지 않은 과거 내역은 복원할 수 없으므로 전체 여행 경비나 완전한 가계부로 표현하지 않는다.
- 취소·환불·정산 등 검증되지 않은 특수 기록은 합산하지 않는다. 이 합계는 전체 여행 경비가 아니다.

## 3. 여러 카드의 잔액 비교

### 다음 타겟 지정 (2026-10-21)

- 사용자가 다음 개선 대상으로 지정했다. 현재 단계는 구체적인 기능·화면 계획 수립 대기이며 구현은 시작하지 않았다.
- 아래 미정 사항을 먼저 검토해 사용자에게 계획을 제시한 뒤 구현 범위를 확정한다.
- 기존 단일 카드 스캔·이용내역·합계 흐름을 보존하고, 비교를 위한 영구 저장이나 IDm 원문 저장·전송을 추가하지 않는다.

### 검토 목적

가족·일행의 카드를 차례로 스캔하고 잔액을 한 화면에서 비교할 수 있게 한다.

### 검토할 내용

- 카드를 연속 스캔하여 현재 세션 안에서 잔액을 나란히 표시한다.
- 카드 IDm이나 이용내역을 영구 저장하지 않는 기존 원칙을 유지한다.
- `카드 1`, `카드 2` 같은 임시 표시명을 사용하는 방식을 검토한다.
- 스캔 시점의 잔액이라는 점을 알리고, 세션 종료 시 비교 정보를 정리하는 방식을 검토한다.

### 아직 정하지 않은 사항

- 동일 카드를 다시 읽었을 때 갱신과 중복 추가를 어떻게 구분할지.
- 비교할 카드 수, 임시 이름 수정, 삭제·초기화·종료 동작.
- 기존 단일 카드 스캔 흐름과 비교 모드의 연결 방식.

## 향후 진행 원칙

- 구현 완료 항목은 결과를 유지하고, 미구현 항목은 별도 구현 요청 전까지 검토·계획 대상으로 관리한다.
- 다음 우선 검토·계획 대상은 `여러 카드의 잔액 비교`다. 첫 스캔 안내와 필터별 합계는 구현 완료로 구분한다.
- 구현 시 기존 코드와 안내를 먼저 점검하여 필요한 변경 범위를 결정한다.
- 기존 UI 구성 요소·하늘색 디자인·타이포그래피·라이트/다크 모드 규칙을 준수한다.
- 카드 IDm 비저장·비전송 및 이용내역 비영구 저장 원칙을 유지한다.
- 검증되지 않은 카드 필드 의미나 거래를 추정하지 않는다.
