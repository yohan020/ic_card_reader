## 라이선스 판단

### 사용 가능성이 높은 정적 지하철 데이터

`input/static/subway_edges.csv`의 근거인 Kyoto City Open Data 「京都市営地下鉄 駅間距離・運賃」은 CC BY 4.0이다. 파생 운임표를 앱 asset으로 넣을 수 있으나, 앱의 데이터 출처 화면 등에 다음 취지의 고지를 유지한다.

> 「京都市営地下鉄 駅間距離・運賃」（京都市）を加工して作成。CC BY 4.0.

원본 데이터셋은 2019년에 마지막으로 갱신되었으므로, 현재 노선과 운임은 별도 공식 페이지로 표본 검증해야 한다.

### ODPT 데이터는 ‘로컬 전용’으로 단정할 수 없지만, 지금 바로 번들에 넣으면 안 됨

ODPT Basic License는 모바일 앱 같은 Deliverable의 상업·비상업 이용을 허용한다. 반면 원본·복제본 또는 원본 전체/대부분을 복원할 수 있는 파생 데이터를 제3자가 재사용 가능한 형태로 공개·재배포하는 것은 사전 서면 승인이나 Specific Terms 근거 없이는 금지한다. Kyoto City Bus·Kyotobus 카탈로그도 Basic License와 **Specific Terms** 확인을 요구한다.

따라서 제공 폴더의 ODPT raw GTFS와 `local_generated/` SQLite를 GitHub·별도 ZIP으로 배포하지 않는 정책은 타당하다. 다만 앱 asset에 들어가는 형태가 허용되는지, 해당 사업자 데이터의 Specific Terms와 실제 asset의 복원 가능성을 기준으로 출시 직전에 확인해야 한다. ODPT를 앱에 쓰는 경우에는 다음도 필요하다.

- ODPT 제공 데이터 사용 사실, 무보증, 앱 개발자 문의처 고지
- 정적 데이터의 취득 시각 표시
- 데이터 변경 통지 뒤 원칙적으로 1주 이내 갱신

근거:

- <https://developer.odpt.org/terms/data_basic_license.html>
- <https://developer.odpt.org/terms/data_basic_use_guideline.html>
- <https://ckan.odpt.org/dataset/kyoto_municipal_transportation_kyoto_city_bus_gtfs>
- <https://ckan.odpt.org/dataset/kyoto_bus_all_lines>

## 구현 전 필수 보완

1. ODPT 계정에서 두 GTFS 데이터셋의 Specific Terms를 확인하고, 앱 번들용 파생 운임 데이터가 허용되는지 기록한다.
2. 실제 최신 GTFS로 importer를 실행해 `fare_attributes.txt`·`fare_rules.txt` 존재와 교토 버스/조정구간 대표 운임을 검증한다. 현재 폴더 테스트는 synthetic GTFS만 사용한다.
3. GTFS importer는 단일 운임 규칙 조회 도구일 뿐, 다중 버스 경로·환승·패스 제외 노선·심야 할증을 자동 판정하지 않는다. 이 규칙을 별도 모델로 설계한다.
4. 앱용으로는 먼저 **지하철 31역 자동완성 + 465개 역쌍 자동 운임 + 버스 횟수/확인된 정액 운임 수동 입력** 범위를 검증하는 편이 안전하다.
5. 버스 전체 자동완성·자동 운임은 위 조건을 충족한 뒤에만 추가한다. 역명 한국어·초성 검색은 기존 교통패스 UI·데이터 정책에 맞춰 별도로 병합한다.

## 결론

이 폴더는 라이선스 위험을 인식하고 ODPT 원본을 제외한 점이 좋으며, **교토시영 지하철 손익 비교의 기반으로는 사용할 수 있다.** 그러나 버스가 이 패스의 핵심이므로, 현 상태로 “교토 전역의 모든 이동을 자동 계산”하는 기능을 출시하면 안 된다. 1차는 지하철 완전 자동 계산과 보수적인 버스 입력으로 제한하고, ODPT 특약·최신 GTFS·제외 규칙 검증 뒤 버스 자동 계산을 확대한다.
